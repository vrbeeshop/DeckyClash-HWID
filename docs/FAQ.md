## Установка

### Как установить именно DeckyClash-HWID?

Этот форк распространяется через [выпуски vrbeeshop/DeckyClash-HWID](https://github.com/vrbeeshop/DeckyClash-HWID/releases/latest). Установите ZIP через **Decky → Настройки → Developer**. Если вкладка скрыта, включите **Developer mode** в разделе **General**. Подробные шаги приведены в [README](../README.md#установка).

Выберите подходящий пакет:

- `DeckyClash.zip` — небольшой пакет плагина, около 4 МБ. При первом запуске мастер установки скачает Mihomo, панели управления и Geo-файлы после выбора **Установить всё**.
- `DeckyClash-full-linux-amd64.zip` — полный пакет с ядром и ресурсами для Steam Deck LCD/OLED и других устройств x86-64.
- `DeckyClash-full-linux-arm64.zip` — полный пакет для устройств ARM64.

Для **Install Plugin from ZIP File → Browse** сначала скачайте или перенесите ZIP на Deck, затем выберите этот файл. Для **Install Plugin from URL** вставьте прямую ссылку на ZIP: Decky скачает его через интернет. Это относится и к полным пакетам. Дополнительный способ установки — небольшой онлайн-скрипт `install.sh`, описанный в README.

### Подойдёт ли версия Decky Clash из Decky Store?

Для функций этого форка используйте его собственные выпуски и инструкции. Название Decky Clash само по себе не означает, что установлен именно DeckyClash-HWID. Встроенное обновление этого форка получает плагин из репозитория `vrbeeshop/DeckyClash-HWID`.

### Почему версия недоступна или загрузка ресурсов завершается ошибкой?

Текущий код получает номер версии из `version.txt`, приложенного к выпуску GitHub. Проверка версии плагина использует [этот файл](https://github.com/vrbeeshop/DeckyClash-HWID/releases/latest/download/version.txt); Mihomo получает свою версию из выпусков `MetaCubeX/mihomo`. Для этой проверки плагин не обращается к GitHub API.

Проверьте доступ к файлам выпусков GitHub и сообщение об ошибке в журнале. Сбой получения версии может быть связан с сетевым доступом, тайм-аутом или отсутствием файла в выбранном выпуске. Если загрузки на Deck недоступны, скачайте полный ZIP нужной архитектуры на другом устройстве, перенесите его на Deck и установите через **Install Plugin from ZIP File**.

## Настройки и журналы

### Где находятся расширенные настройки?

По умолчанию настройки хранятся в `~/homebrew/settings/DeckyClash/config.json`. Здесь можно задать `user_agent_override`, `log_level`, тайм-ауты и другие параметры. Список настроек есть в [руководстве для разработчиков](./DEV_GUIDE.md).

После ручного редактирования сохраните корректный JSON и перезапустите Decky Loader, чтобы плагин перечитал настройки:

```sh
sudo systemctl restart plugin_loader.service
```

Перезапуск остановит работающий экземпляр Mihomo, запущенный плагином.

### Где искать журналы и как включить подробный вывод?

Журналы плагина находятся в `~/homebrew/logs/DeckyClash`. Вывод ядра Mihomo записывается в `core.log`; этот файл открывается заново при запуске ядра.

Для подробного журнала укажите `"log_level": "DEBUG"` в `config.json` и перезапустите Decky Loader. По умолчанию используется `INFO`; также поддерживаются `WARNING` и `ERROR`. Перед отправкой журнала удалите из его копии ссылки на подписки, пароли и другие секреты.

## Подписки и HWID

### Как добавить или загрузить подписку из файла?

Откройте **Decky Clash → Импорт**, введите ссылку на подписку Clash/Mihomo и запустите загрузку. Внешний импортёр на этой же странице позволяет открыть веб-панель по QR-коду или адресу и загрузить подписку по ссылке либо отправить файл конфигурации. Имя можно изменить после импорта в разделе управления подписками.

Профили сохраняются в `~/homebrew/settings/DeckyClash/subscriptions/<имя>.yaml`. Файл, отправленный через внешний импортёр, сохраняется как локальная подписка и не обновляется по сети. Для обновляемой подписки добавляйте её HTTP(S)-ссылку.

### Откуда берётся HWID и нужно ли его вводить вручную?

Если сохранённый идентификатор ещё не задан, плагин создаёт случайный UUIDv4 и сохраняет его в `subscription_hwid` в `config.json`. Этот идентификатор используется в заголовке `X-Hwid` при скачивании и обновлении удалённых подписок. Вводить его вручную для обычного использования не требуется.

HWID сохраняется между перезапусками и входит в резервную копию настроек. Удаление настроек приведёт к созданию нового идентификатора; восстановление резервной копии вернёт идентификатор из этой копии. Отсутствующее или некорректное значение `subscription_hwid` также заменяется новым UUIDv4 при загрузке настроек. Смена идентификатора может быть воспринята провайдером как новое устройство.

### Какие данные об устройстве отправляются провайдеру?

При скачивании и обновлении удалённых подписок плагин также отправляет:

- `x-device-os: Linux` — семейство операционной системы SteamOS.
- `x-ver-os` — версию ОС из `VERSION_ID` в `os-release`. Если значение недоступно, пусто или непригодно для HTTP-заголовка, отправляется `unknown`.
- `x-device-model` — `Steam Deck LCD` для DMI-модели Jupiter или `Steam Deck OLED` для Galileo. Если модель определить не удалось, используется `Steam Deck`.

Эти данные определяются автоматически. После обновления ОС перезапустите плагин или Decky Loader, чтобы обновить передаваемую версию; перезагрузка устройства также обновит эти данные. Сохранённый HWID остаётся прежним. Для импорта через внешний импортёр, ручного и автоматического обновления используются те же заголовки.

### Что означает «Достигнут лимит устройств для этой подписки»?

Сервер подписки вернул заголовок `x-hwid-max-devices-reached: true`. Удалите неиспользуемое устройство в личном кабинете провайдера, если такая возможность доступна, или обратитесь к провайдеру.

Плагин проверяет этот заголовок и при HTTP 200, и при HTTP-ошибках. При отказе обновления ранее сохранённая конфигурация остаётся на месте. Сообщение отображается при импорте, ручном обновлении и автоматическом обновлении подписок.

### Почему показывается «Не удалось получить подписку. Подробности в журнале плагина»?

Так отображаются другие HWID-ограничения, обозначенные сервером заголовками `x-hwid-not-supported` или `x-hwid-limit`, когда нет более точного признака достижения лимита устройств. Подробная причина записывается в журнал плагина. При отказе обновления сохранённая конфигурация не заменяется ответом сервера.

### Почему та же ссылка возвращает другой профиль в другом клиенте?

Провайдер может выбирать формат подписки по `User-Agent`. По умолчанию плагин отправляет встроенный User-Agent для клиентов Mihomo/Clash. Если провайдер требует другое значение, его можно указать в `user_agent_override` в `config.json`, затем перезапустить Decky Loader. Пустое значение возвращает встроенный User-Agent. Этот параметр меняет только `User-Agent`: HWID и заголовки ОС, её версии и модели устройства сохраняются.

### Как переопределить настройки профиля?

Шаблоны TUN, DNS и общие переопределения находятся в `~/homebrew/plugins/DeckyClash/override.yaml`. Переключатель переопределения DNS доступен в интерфейсе плагина. Подробности структуры и примеры приведены в [файле шаблона](../defaults/override.yaml).

Сохраните отдельную копию своих изменений: обновление плагина заменяет файлы в его каталоге, включая `override.yaml`.

## Обновления

### Как обновить плагин, Mihomo и ресурсы?

Откройте **Управление обновлениями** в плагине. DeckyClash и Mihomo имеют отдельные строки с установленной и доступной версиями, выбором канала и кнопками обновления. Ядро Mihomo обновляется отдельно от плагина; архив выбирается по архитектуре устройства. Geo-файлы и панели управления переустанавливаются отдельными кнопками на той же странице.

Если включена автоматическая проверка, плагин проверяет новые версии при загрузке и показывает уведомление при наличии обновления. Для ручной проверки нажмите на доступную версию на странице обновлений. Плагин можно также обновить установкой нового ZIP по [инструкции в README](../README.md#установка).

### Почему вместо последней версии показан крестик?

Крестик означает, что интерфейс не получил доступную версию. Проверьте загрузку `version.txt` для выбранного канала и журнал плагина. Для плагина предусмотрены каналы последнего выпуска и ночной сборки; для Mihomo — стабильный канал Meta и Alpha. Отсутствие файла выпуска или ошибка сети не означает, что установленная версия повреждена.
